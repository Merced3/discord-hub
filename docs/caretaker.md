# Server caretaker channels

## Ownership boundaries

- **`#how-to`** is fully generated by Courier from redacted project command
  declarations (ADR 0013). Do not hand-edit its generated reference; change the
  owning project's command declaration instead.
- **`#about`** is stable, human-approved server orientation. It explains where
  to go and why the server is organized that way. It is not a command mirror,
  status dashboard, changelog, or duplicate list of every channel.
- **`#announcements`** records notable changes. Routine command-description
  synchronization does not require an announcement.

The caretaker may propose an `#about` revision when the server's purpose,
category organization, or an important convention changes. It must present the
proposed text and apply it only after explicit owner approval. It must not
continually rewrite the channel, infer private meaning, or clean up its history.

• **Community** — general chat and server suggestions.
• **AI** — Socratic reflection and teaching.

Channel topics explain the purpose of each space. Conversation-based agents use threads to keep sessions separate. Use the commands in #how-to rather than manually imitating an automation's output.

#about explains where and why. #how-to explains commands. #announcements records notable changes.
